# Hyprland Keybind Studio (HKS) — Phase 3a: Editing UI & Services

## 1. Overview

Phase 3a connects the Safe Edit Engine (Phase 4a) to the Quickshell GUI frontend, providing a safe, verified visual workflow for disabling, enabling, deleting, and restoring keybindings in `hyprland.lua` and `hyprland.conf`.

Every edit follows a strict **preview-first** pattern:
1. **Preview (Dry-Run)**: The frontend executes the CLI with `--json` in dry-run mode. Zero files are modified.
2. **Confirmation Modal (`EditConfirmDialog.qml`)**: The user inspects the unified diff, verification badges, and warnings. Destructive operations (Delete) require an explicit second checkbox confirmation.
3. **Atomic Apply & Reload**: On user confirmation, the CLI applies the edit, verifies the file, writes an external backup, and triggers `hyprctl reload config-only`.
4. **Auto-Rescan & Toast Notification**: The UI automatically rescans the active configuration and displays a floating toast with an instant "Undo" option.

## 2. Architecture & Components

### 2.1 `EditService.qml` — Frontend Edit Coordinator

`EditService.qml` is a Quickshell singleton that manages CLI interactions via `Process` with uniform `--json` responses:
- **Asynchronous Execution**: Commands (`edit`, `backups`, `restore`) run asynchronously with a 15-second timeout guard.
- **Dry-Run Safe Mode**: When `HKS_EDIT_DRYRUN_ONLY=1` or `HKS_FIXTURE` is set, writes are disabled and the dialog displays `"Apply (disabled in test mode)"`.
- **Toast & Undo History**: Tracks active operations, displays toasts with action summaries, and provides single-click Undo triggering `restore --latest`.
- **Automatic Rescan**: Calls `KeybindData.reload()` and `loadBackups()` upon successful edits.

### 2.2 `EditConfirmDialog.qml` — Modal Verification & Diff Viewer

A modal dialog rendered above the window content:
- **Verification Badges**:
  - *Hyprland Verify*: Displays whether `Hyprland --verify-config` passed (`OK`), failed (`FAILED`), or was skipped.
  - *Bind Count Diff*: Displays the bind multiset delta (e.g. `Binds: 123 → 122 (+0 / -1)`).
- **Unified Diff Viewer**: Monospace, syntax-colored diff lines (`+` green, `-` red, `@@` cyan) with vertical scrolling.
- **Destructive Action Safeguards**: For Delete operations, the Apply button is locked until the user explicitly checks `"I understand this permanently deletes the keybinding line"`.

### 2.3 `Disabled.qml` — Disabled Keybindings Management

A dedicated page accessible from the sidebar displaying keybindings disabled by HKS:
- **Scan Detection**: Scanner identifies lines starting with `-- HKS-disabled: ` or `# HKS-disabled: ` and emits `disabled_binds`.
- **Key & Description Hints**: Displays the original key hint, description, source location (`file:line`), and code snippet.
- **Re-enable Action**: An "Enable" button triggers `EditService.requestUncomment(disabledBind)`, previewing and restoring the line to active status.

### 2.4 `Backups.qml` — Configuration Snapshot History

A dedicated page for managing backups stored in `~/.local/share/hks/backups`:
- **Snapshot Listing**: Displays creation timestamp, original file path, and short SHA-256 hash.
- **Restore Action**: A "Restore" button previews the diff between the current config and the backup snapshot, allowing safe rollback.

### 2.5 Safety & Window Mode Isolation

- **Window Mode Only**: Edit action buttons (Disable, Delete) appear only in window mode (`scripts/hks-window`). Popup mode (`scripts/hks-popup`) remains strictly read-only.
- **Loop-Generated Binds Guard**: Binds created via loops (`bind.generated === true`) cannot be edited as single lines. They display an explanatory banner: `"generated by a loop at ~/.config/hypr/hyprland.lua:..., edit the loop instead"`.
- **Companion File Warning**: Persistent banner appears when `hyprland.conf` exists alongside `hyprland.lua`: `"hyprland.conf is not modified by HKS"`.

## 4. Scope Boundaries & Deferred Features

The following features are explicitly outside the scope of Phase 3a:
- **Arbitrary Bind Addition / Modification**: Adding brand new keybindings or editing keys/dispatchers arbitrarily is deferred to Phase 3b.
- **Interactive Keybind Recorder**: Recording physical keystrokes via Wayland hooks is deferred to Phase 3b.
- **Dispatcher Picker & Argument Form**: Structured parameter entry for dispatchers is deferred to Phase 3b.
- **Companion `.conf` Modification**: HKS edits only the primary active entrypoint. If `hyprland.lua` is active, `hyprland.conf` is left untouched.
- **Loop Binds Editing**: Single-line edits cannot represent changes to programmatic `for` loops.
