# Phase 2b-2a: Conflicts Page (Read-Only Desktop Client)

Phase 2b-2a adds a dedicated **Conflicts** inspection view to the Hyprland Keybind Studio (HKS) desktop window client.

It provides a categorized, visual breakdown of colliding shortcuts—differentiating between illegal/redundant duplicates and intentional stacked bindings (such as `ALT+Tab` multi-dispatcher chains).

---

## 1. Data Model & Architecture

The Conflicts page consumes the existing JSON contract from `KeybindData.conflicts` and `KeybindData.binds`:

- **Conflicts**: Array of `{id, kind, severity, submap, modifiers, key, bind_ids, sources}`.
  - `kind === "duplicate"`: Multiple bindings sharing identical key combinations and identical dispatchers. Redundant.
  - `kind === "multiple_actions"`: Multiple bindings sharing the same key combination with different dispatchers. Legal; executed sequentially by Hyprland.
- **Binds Lookup**: Individual bindings are retrieved safely by `id` using `KeybindData.getBindById(id)`. If an ID is missing or unregistered, the interface degrades gracefully to `(Unknown bind: <id>)` without crashing or throwing QML errors.

### 1. Sidebar Integration
- The sidebar navigation item **"Conflicts"** is fully enabled and active.
- Displays a dynamic badge showing the total number of conflicts (`String(KeybindData.conflicts.length)`).

### 2. Header Summary
- Title: **Keybinding Conflicts**.
- Summary Badge: `"N conflicts: X duplicate, Y stacked"` (tinted red/critical if any duplicates exist, else yellow/warning).
- Context note: `"Stacked binds are legal: Hyprland runs every bind that matches a keypress."`.

### 3. Sorting & Grouping
- Conflicts are ordered with **duplicates first** (worst severity), followed by **stacked bindings**, preserving original scan discovery order within each group.

### 4. Conflict Card Structure
Each conflict is rendered inside an elevated card:
- **Header Line**:
  - Shortcut displayed using native `Keycap` chips.
  - Kind pill: `Duplicate` in critical red (`#e06c6c`) or `Stacked` in warning yellow (`#d79921`).
  - Submap indicator (if non-default).
  - Total bind count.
  - **"Show in list" Button**: switches to the All Keybindings view with the search filter prefilled to the shortcut tokens (e.g. `"alt tab"`) and category reset to `"All"`.
- **Explanatory Sentence**:
  - Stacked: `"Pressing this triggers all N actions."`
  - Duplicate: `"These binds do the same thing; one of them is redundant."`
- **Fixed-Column Bind Table**:
  - Column 1: Description text (`width: 250px`, primary font).
  - Column 2: Dispatcher and arguments (`font.family: monospace`, muted, fills remaining space).
  - Column 3: `loop` badge (when generated by loops) and source file path with `$HOME` replaced by `"~"` (`width: 240px`, right-aligned).

### 5. Empty State
- When `totalConflicts === 0`, renders a clean centered card:
  - Icon: `` (checkmark).
  - Title: `"No conflicts found"`.
  - Message: `"Every keybinding in this configuration has a unique key combination."`.

### 6. Keyboard Controls
- **Up / Down Arrows**: Scroll the conflicts list viewport.
- **Esc**: Returns to the All Keybindings view.
- **Ctrl+R**: Triggers a background config rescan.
